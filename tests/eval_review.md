## 二、根本原因与修复

### 🔴 P0 — 索引与搜索使用了不同模型（已修复）

| | 索引 (embed_and_load.py) | 搜索 (search_server.py) |
|:---|:---|:---|
| 模型路径 | HF cache `BAAI/bge-m3` (PyTorch) | 本地 `models/bge-m3` (ONNX) |
| Sparse 向量 | **0 tokens（全部为空）** | 正常（7 tokens） |
| Dense 向量相似度 | cos_sim = **0.3888**（近乎正交） | |

两个"BGE-M3"实质上是不同的模型。HF PyTorch 版完全不产生 sparse 向量，导致 Qdrant 中 82 条 chunk 的 sparse 全是空的，RRF fusion 退化为纯 dense 排名。而 dense 向量在两个模型间差异巨大（cos_sim=0.39），即使 dense 排名也是基于错误的向量空间。

**修复**：将 `embed_and_load.py` 改为加载本地 ONNX 模型（与 `search_server.py` 一致），重建 Qdrant。

### 🟡 P1 — npy.float32 JSON 序列化 bug（已修复）

`embed_and_load.py` 第 68 行 `list(w.values())` 保留了 numpy float32 标量，json.dump 无法序列化。此前未暴露因为 sparse 全为空（空 list 不触发）。改为 `[float(v) for v in w.values()]`。

## 六、P1 修复（已实施）

### P1a: 前置拒答（`search_server.py` L897-910）

在 LLM 生成前增加 relevance gate：提取查询中的实义词（排除"怎么""如何"等停用词），检查 Top-3 chunk 是否有**至少一个词重叠**。若无 → 跳过 LLM，直接返回：

> "知识库中未找到相关信息。该问题可能超出本说明书的覆盖范围，建议联系雅迪授权服务站或拨打400-900-1212咨询。"

**预期效果**：Q001-Q005 "说明书没有"类查询全部被前置拦截，Rejection Rate 从 20% → 100%。

### P1b: Ollama 重试（`search_server.py` L598-622）

`_generate_answer` 增加重试逻辑：超时后等待 2s/4s 重试（共 2 次 retry + 1 次 initial = 最多 3 次尝试）。连接错误和 HTTP 错误不重试（非瞬态）。

**预期效果**：减少 `⚠️ AI 生成服务暂时不可用` 降级次数，Answer 报告中的 Groundedness 不再被降级答案拖低。

## 九、优化路线（最终）

### 3 条失败的本质

| 查询 | chunk 用词 | 问题类型 |
|:---|:---|:---|
| "灯不亮了" | "大灯是否**正常工作**" | 口语→书面同义替换 |
| "最高速" | "最高车速25km/h" | 2字极短，embedding 信息量不足 |
| "电池怎么安装" | "电源连接器""蓄电池提手" | 语义接近但用词不同，排名不够 |

### 不是多轮问题

这三条都不需要 ReAct（多轮推理）。用户在单轮内表达了完整意图，问题是**查询词和 chunk 词不在同一空间**——这是 Query Rewriting 的典型场景。

### 方案：Layer 1 Query Rewriting → Layer 2 ReAct

```
Layer 1: LLM Query Rewriting（单轮，前置）
  输入: "灯不亮了"
  输出: "大灯故障 不工作 灯光异常"
  方法: 用小 prompt 让 LLM 把口语转为书面检索词
  适用: 同义替换、缩写展开、极短查询补全

  输入: "最高速"
  输出: "最高车速 最大速度"

  输入: "电池怎么安装"
  输出: "蓄电池 安装 装配 步骤"

Layer 2: ReAct Agent（多轮，仅 Layer 1 改写后仍不命中时触发）
  Thought → Action(检索) → Observation → Thought → Action(改写) → ...
  适用: 复杂故障需要推理链、多次检索才能定位根因
  示例: "骑行时一顿一顿的是什么问题" → 可能涉及电机/控制器/电池多个子系统
```

### 实施建议

1. 在 Phase 1（Query Expansion）之前插入 LLM Rewriting 步骤
2. 用轻量 prompt（temperature=0.1, num_predict=50），延迟可控
3. 改写结果替代原 query 进入 encode → search → rerank 流程
4. ReAct 留待后续复杂故障场景再做

### 预期效果

| 查询 | 改写后 | 预期结果 |
|:---|:---|:---|
| "灯不亮了" | "大灯 灯光 不亮 故障" | tbl102 命中 |
| "最高速" | "最高车速 最大速度" | tbl126 命中 |
| "电池怎么安装" | "蓄电池 安装 装配" | stp045 命中 |

→ Recall@5 从 84% → 90%+（45 条中全部命中）
